**27 October 2026 (`orca-move` 0.1.2, sessions without the mod):** plugins load when a session starts, so a session started before orca-move was installed has no mod to run `/exit`, and `go` used to promise an automatic exit that never came (an orchestrator armed two moves that way; the person typed `/exit` both times). `plan` and `go` now check: the process's own arguments name orca-move (a plugin folder), or its start time (`procStart`) is after the earliest `installedAt` of `orca-move@*` in the account's `installed_plugins.json`. When it is not, `go` says to type `/exit` (the helper still resumes the tab), and the skill puts that first in its last message.

**27 October 2026 (`orca-move` 0.1.1, cancel):** `/orca-move:switch cancel` (`move.py cancel`) withdraws a pending move: stops this session's helper, removes the exit request, resume script and plan file, keeps the note as `<id>.cancelled.md`, and the skill recreates the crons and tells the peers it is not moving. **27 October 2026 (new plugin `orca-strator` 0.1.0, skills `conduct`, `join-lane`, `join-checker`, `hand-over`, the fourth Orca Strator plugin):** runs a fleet of sessions on one project. `conduct` makes the orchestrator: reads a handoff note, creates a status cron (`conduct status`: every fleet session's context use from orca-peers `--json`, handover nudges at 70% and 85%, the merge queue) and a nudge cron (`conduct nudge`: idle lanes with work left), tells the fleet to report to it, keeps the orders file. `join-lane` and `join-checker` brief the other roles; merge rights always come from the project's own rules file. `hand-over` writes the role's note and, with `start`, opens the successor in a new Terminal window with `scripts/successor.py` (same `CLAUDE_CONFIG_DIR`, `command claude` so a shell function cannot change the account, `CLAUDE_CODE_PLUGIN_DIRS` passed on); the successor tells both the orchestrator and its predecessor it took over. Project facts live in `.claude/orca-strator.json` (example in `templates/`), plus templates for the three handoff notes, orders, preview ledger and open items. Dry run in a throwaway repo with two sessions: the orchestrator created both crons and the notes files, the lane joined and reported by itself, did its task, and handed over to `#2`, which reported in unprompted. Two fixes came out of it: no default fleet prefixes (the defaults `Lane` and `Checker` would have matched another project's live lanes), and the successor now tells its predecessor it can close.

**27 October 2026 (new plugin `orca-move` 0.1.0, skills `switch`, `switch-all`, `after-move` and one mod, the third Orca Strator plugin):** moves a live session to a twin account (a config dir sharing `projects/`, so `claude --resume` opens the same transcript). `switch` tells the sessions it works with, writes a move note (crons, background work, who to tell, what it waits on) to `~/.config/orca-strator/moves/`, deletes its crons, then `move.py go` writes a resume script and starts a detached helper. **27 October 2026 (new plugin `orca-accounts` 0.1.0, a mod, the second Orca Strator plugin):** shows every account's 5-hour and 7-day usage in one band above the prompt.
